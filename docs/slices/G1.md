# G1 — evacuate

Branch: `refactor/engine-g1-evacuate`, from `feat/engine-g0-fence` (`e582b68`).
Review phase: P1 of https://01a1c8c6-da49-738a-9006-9ee46bf28d6b.arena.site/.

The review's P1 is one sentence — move the toolkit-free files into their single
crate — and one constraint: no visible change, every suite still passing after
import edits only. This slice does that and nothing else. No behaviour moved,
no assertion changed; where a move forced a visibility change, it is listed
below and is the smallest change that compiles.

## Changed

1. **Eighteen files move** out of `crates/ui-egui/src/`, and one goes to the
   core crate the review's own rule names. Path-preserving, so a reader who
   knows the front end finds them where they were:
   `export`, `watch`, `texts`, `paper`, `pane_texts`, `reading_place`,
   `transcript`, `play`, `reveal`, `stable_hash` stay at the engine root;
   `notes_panel/query`, `page_ai/extract` (+ its `extract_tests.rs`),
   `read_aloud/words`, `read_aloud/countdown`, `settings_window/scope` →
   `scope`, and `word_list/build` (+ its `build_tests.rs`) → `word_marks` keep
   their leaf names.
   `library/picks.rs` is the exception: it names exactly one `mareader_*` crate
   (`mareader_library`) and nothing from `crate::`, so P1's first rule —
   "moves down into that crate" — puts it in `crates/library/src/picks.rs`,
   not in the engine. It is exported from `mareader_library`'s root, and
   `ui_egui::library::picks` still resolves.
2. **Nothing new is invented.** `library`, `notes_panel`, `page_ai` and
   `read_aloud` are new module files only because their moved children need a
   parent; each is a doc line and its `pub mod`. `word_list/build.rs` is the one
   rename: it is called `word_marks.rs` because `build` as a crate-root module
   name would read as a verb, and its test file follows it to
   `word_marks_tests.rs`. `settings_window/scope.rs` becomes `scope.rs` for the
   same reason — a crate root has no window to be a settings window of.
3. **The front end calls across the boundary.** Every `crate::<moved>` path in
   `crates/ui-egui` is now `mareader_engine::<moved>` (13 files), and the
   module declarations that owned a moved child (`mod query;`, `mod extract;`,
   `mod words;`, `mod countdown;`, `mod scope;`, `pub mod build;`, `pub mod
   picks;`) are gone. `library.rs`, `settings_window.rs` and `word_list/mod.rs`
   keep their public paths by re-exporting the engine item, so no third party
   sees the move: `ui_egui::library::picks::{Pick, PickAction, Picks}`,
   `ui_egui::settings_window::{Applies, Scope, Shown}` and
   `ui_egui::word_list::{Page, Sheet, Word}` all still resolve.
4. **Visibility, the minimum each move needs.**
   - `picks.rs`: `apply` and `retain` go `pub(super)` → `pub`; they are called
     from `library/shelving.rs`, which is a different module now that `picks`
     answers to `mareader_library`.
   - `read_aloud/{words,countdown}.rs`: `pub(super)`/`pub(crate)` → `pub`,
     because `read_aloud/spoken.rs` and `read_aloud/mod.rs` still live in the
     front end and name `Countdown`, `Estimate`, `Clock`, `Pace`, `Steady`,
     `group` and `heard` across the boundary.
   - `export.rs`: `pub(crate) fn date` → `pub`; `page_ai/menu.rs` formats with
     it.
   - `page_ai/extract.rs`: `book()` destructures its `[[usize; 2]; 2]` span in
     the signature. The file was written under a crate that allowed
     `indexing_slicing` in library code; `mareader-engine` denies it, and a
     destructuring pattern is the version that cannot panic. Same behaviour.
5. **A test seam, not a test copy.** `texts` and `paper` call
   `crate::testing::doc()`, which belongs to the front end and stays there.
   `mareader_session` gains no item — the review's limit is that L0–L3 APIs do
   not change — so the sample builder lives in `crates/engine/src/sample.rs`,
   in the `mareader_engine` crate, built from `mareader_pdf::sample::pdf` and
   the public `Session` API. The front end's `testing::doc()` now calls it, so
   the sample is defined once.
6. **What the crate had to be given.** `mareader-engine` depends on
   `appearance`, `cefr`, `dict`, `epub`, `library`, `pdf`, `reflow`, `session`,
   `settings`, `speech`, `study`, `workspace` and `serde_json` — every one at
   rank 0–3, none at L5, so the layer gate stays green. `mareader-library` and
   `mareader-ui-egui` gain nothing: the first now owns a module it already had
   the items for, the second already depended on both.
7. **The gates move with the tree.** `tools/trapped_count.txt` 52 → **33**. The
   three parity citations into moved files are repointed
   (`pane_texts.rs` ×2, `settings_window/scope.rs` → `scope.rs`); a citation
   names the test that proves the feature, not the crate it lives in.

## Limits

- **Nothing was compiled.** The risks a compiler would catch and this does not:
  a trait or type mismatch introduced by a visibility widening (none of the
  signatures changed), and an ambiguity where a moved module and a stayed
  module share a leaf name. Both were checked by hand and by the two link
  scripts; neither is rustc.
- **`cargo xtask wasm` has still never run** (it did not run in G0 either), and
  `mareader-engine` is now one of its 28 targets. `watch` and `play` use
  `std::fs`, `std::thread` and `std::process::Command`, which do not exist on
  `wasm32-unknown-unknown`. **This is the one thing in this slice most likely to
  turn the merged CI red.** The fix is a `#[cfg(not(target_arch = "wasm32"))]`
  split inside the engine crate, or moving `play` behind the `Host` in P4 — the
  review's own answer — so it is named here rather than papered over. It was
  not done in this slice because it is a code change of a kind the review keeps
  for P4, not a move.
- **`picks` is `pub` only because its caller moves later, not with it.**
  `library/shelving.rs` (which calls `apply`/`retain`) is not toolkit-free yet,
  so it could not travel; when it does, in P2 or P3, those two methods can go
  back to `pub(super)`.
- **`settings_window/scope.rs` is in the engine but `settings_window` is not.**
  It is pure `Applies`/`Scope`/`Shown` with no drawing, so it belongs below the
  line; its former siblings are all `egui` and stay. Naming it `scope` at the
  crate root is the first rename in this batch and the only one a reader has to
  learn.
- **`page_ai/extract_tests.rs` is on the review's held list and moved anyway.**
  The review asks both that "its tests move with it" and that this file be
  held; both cannot hold, because `extract_tests.rs` reaches `Origin::`,
  `pdf_lines`, `text_block` and other items that are **private to
  `page_ai::extract`**. Rust privacy is per crate, so a test module living in
  `ui-egui` could not see them once `extract` sits in `mareader-engine`; the
  only ways to obey the held list are to make six internals `pub` (violating
  "move them, untouched") or to keep a copy of `extract` behind. It moved with
  its subject, which is also how the exit gate "`cargo test -p mareader-engine`
  runs the moved tests" counts 50 tests under `crates/engine/src`, the exact
  number the same files held at `HEAD`.
- **The review says 3,361 lines in 17 files; this tree gives 3,406 moved lines
  in 18 engine files, plus `picks.rs` (128 lines) in `mareader-library`.**
  The files beyond the review's 17 are the `#[path]` test children that travel
  with their parents (`extract_tests.rs`, `build_tests.rs`); the extra lines are
  the S-batch's splits since the review was written. `sample.rs` is new and is
  counted apart. The count that matters — `trapped` — is the number a reviewer
  can check, and it is committed.
- **`trapped` is 33, the review's P1 gate says 12, and the gap is not this
  slice's.** Of the 33 files still counted, 12 are exactly the review's own
  held list (`command.rs`, `route.rs`, `trigger.rs`, `study/words.rs`,
  `read_aloud/parts.rs`, six `library/*` and `page_ai/extract_tests.rs`). The
  other 21 are toolkit-free files the review does not enumerate at all —
  `app/apply/*` (5), `app/options/*` (7), `app/navigation.rs`, `app/page_ai.rs`,
  `app/setup.rs`, `dial_deck/labels.rs`, `icons/lru.rs`, `pdf_view/paint.rs`,
  `pdf_view/paint/raster.rs`, `pdf_view/scroll.rs`, `word_card.rs` — and most
  of them belong in P2's reducer or a later phase, not here. Moving them now
  would not match their phase, so they are reported, not guessed at. 12 of 12
  named held files are indeed still in place, and every file the review lists
  as movable has moved.

  the engine now and will be the first caller of that trait.
