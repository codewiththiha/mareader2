## Changed

1. **The rename.** `git mv crates/ui crates/ui-egui`; package `mareader-ui` →
   `mareader-ui-egui`; workspace key and both apps updated; `Cargo.lock`
   updated by hand (entry renamed, re-sorted by name, `mareader-engine` added)
   because no compiler runs in this sandbox.
2. **The engine floor.** `crates/engine` (`mareader-engine`, L5): an empty
   library with the standard `deny(clippy::{unwrap_used, expect_used, panic,
   unimplemented, todo, unreachable, indexing_slicing})` block and
   `[lints] workspace = true`. It has no items, so nothing can import a shim
   that would have to be deleted later.
3. **The layer table.** `("engine", Layer::Core(5))`, `("ui-egui",
   Layer::Front)`, `Front` ranked 6, a new `Layer::App` ranked 7 for
   `mareader`, `web` and `cli`, and `HEADLESS = "cli"`: the client may not
   depend on `mareader-ui-egui` or any crate in `UI_CRATES`, and that is a hard
   error, not a comment.
4. **`cargo xtask wasm`.** Checks every L0–L5 crate, `mareader-ui-egui` and
   `mareader-web` with `cargo check --locked --target wasm32-unknown-unknown`,
   in layer order, stopping at the first failure. Targets come from the same
   `TABLE` the layer gate reads, so a new crate is covered the commit it lands.
   `assist` is the one exemption, declared with its reason in `EXEMPT`.
5. **`cargo xtask trapped`.** Fails when a file under `crates/ui-egui/src` names
   no toolkit and is not on the allowlist (`lib.rs`, `icons/pack.rs`), exactly as
   the review scopes it. `tests/` and `examples/` are harnesses and are not
   counted, or P3's "count reaches 0" could never hold. The ceiling lives in
   `tools/trapped_count.txt` and may only fall.
6. **Wiring.** Both gates are in `xtask ci`; `ci.yml`'s `Rust / test` job runs
   them with `rustup target add wasm32-unknown-unknown`; `remote.yml` gains
   `cargo xtask wasm` and `cargo xtask trapped`, and its
   `|| echo "::warning::…"` escape is deleted, so the wasm lint is now fatal.
   `rust-toolchain.toml` pins the wasm target with the toolchain.
7. **The ripple the rename owed.** All 521 parity evidence paths (they cite
   files, not tests), `ATTRIBUTION.toml`'s icon usage line, `shape_baseline.toml`
   keys, `tools/comment_check.py`'s example, `tools/ci.py`'s warm-cache
   fingerprint, `remote.yml`'s five `-p mareader-ui` builds, `xtask`'s doc text
   and the command descriptions in `main.rs`.
8. **Docs.** `docs/architecture.md` gains the L5/L6/L7 rows, rules 3 and 4, the
   `assist` exemption where `assist` is described, and a revision row.
   `AGENTS.md` § Layering states the engine-first shape and both new gates, and
   its gate block runs them. `CLAUDE.md` names `crates/engine` and the new
   commands. `ROADMAP.md` records the fence.

## Limits

- **Nothing was compiled.** The rename is textual, so its risks are a missed
  import (none found by grep: zero remaining `mareader_ui`/`mareader-ui`/
  `crates/ui` references outside the two history lines that describe the move),
  a lock entry cargo would rewrite differently (checked by sort order), and the
  new gates' own Rust compiling first time (reviewed by hand, not by rustc).
- **`cargo xtask wasm` has never run.** It is new, and this sandbox has no
  toolchain. Its Python-side target list and its own unit tests are the only
  evidence; the first real run is the merged CI pass the owner asked for.
- **`wasm` may be red on the first merged run** for a crate whose
  `cfg(not(target_arch = "wasm32"))` story was never exercised by a gate. That
  is exactly what the review says cannot stay hidden, and it is the one result
  that would need a follow-up slice, not a silent exemption.
- The count `52` is the honest number for this tree; it is higher than the
  review's 30 because the S-batch split large files into more, smaller
  toolkit-free ones (its 17 candidates became 52 files by the same test).
