# S0 — review foundation

## Changed

Added shape baseline and size/duplicate scanner, separate comment budgets,
pre-push hook, pinned Rust toolchain, gated CI, cache GC, batch ownership and
reuse index. Updated agent instructions and corrected stale Claude guidance.
Remote shots and memory use the test cache environment; build caches only save
on main. CI checks the PR head rather than GitHub's generated merge commit.

## Verified

- Python comment scanner self-test passes, including doc and comment exemptions.
- Shape initialization recorded 116 files and 95 functions; the check passed.
- A staged 501-line fixture was rejected; it was then removed.
- Comment budget passed, Python files compiled, shell hook passed `sh -n`, and
  workflow YAML parsed with PyYAML.
- The pinned Rust release manifest exists on static.rust-lang.org.

## Limits

The owner asked to defer all CI and merges. No Rust toolchain is installed here,
so rustfmt and Rust checks were not run. The workflow, actual cache sharing,
PR events and timing require the final CI run. Cache purge is an owner action
and was not run. The shape scanner is the review's lightweight heuristic, not a
Rust parser: comments, strings, same-named functions and moved functions may
cause inaccurate results. Duplicate enforcement remains off until SZ. Rules
such as doc contracts and commit bodies still require review. The review's S0
write-set does not include `tools/commit_check.py`, so its existing checker
still only enforces subject length, not body or performance measurements.

## Seen, not touched

The review requests placeholder modules in S0 but excludes their source files
from S0's write-set; the batch plan assigns module-list edits to their owning
slices instead. The review's prescribed main-first CI warm-up conflicts with
the owner's deferred-merge instruction; follow the owner. Cargo.toml's stale
unsafe comment is outside S0's write-set and is assigned to S4.
