# G2 — the reducer

Branch: `refactor/engine-g2-reducer`, from `refactor/engine-g1-evacuate`
(`566b75f`). Review phase: P2 of the review site. This slice is the one that
makes Mareader engine-first, and it is being done in stages, each committed.

## Stage 4 — the split

`Command` becomes two enums and one door. Applying Law 4 — replayed with no
window, does it change what the next launch shows, what is on disk, or what is
heard? — gives **59 engine variants and 20 chrome**:

| | |
| --- | --- |
| `engine::command::Intent` | panes, pages, the library, study marks, AI, speech, settings writes, exports, `Ai` |
| `ui_egui::command::UiCommand` | the sidebar, popovers, the settings window, find, notices, window buttons |
| `ui_egui::command::Command` | `Intent(Intent)` or `Ui(UiCommand)`, with `From` for both |

Evidence decided the arguable ones rather than taste: `SetSidebarOverlay` and
`SetTitlebarPinned` write `settings.chrome`, so they are intents; the
sidebar's *visibility* is not stored anywhere, so toggling it is chrome.
`TryVoice` is heard, so it is an intent even though no state changes.
`WindowCommand` went back up to `ui-egui`: it is pure chrome and the engine
has no business naming it.

`Toast` moved down with an `Option<Box<Intent>>` for its button, and the three
real Undo call sites now pass an intent. The two screenshot fixtures used to
name `ClearToasts`; that is chrome and cannot be an undo target, so they name
`Study::Restore` of an empty list — the same "put these marks back", over
nothing.

## Verified here (no compiler)

- **79 variants in, 79 out.** Every variant at the branch point exists in
  exactly one of the two enums, none invented (the first run did invent five:
  `WindowCommand`'s, and they were sent back up).
- **`route::reads` is still exhaustive.** It is the one place that must decide
  a home for every command; it covers 20/20 ui and 59/59 engine variants,
  each exactly once. Writing it caught three real mistakes (`CloseSettings`
  and `ShowAppearance`/`ShowSettings` classified on the wrong side).
- **`apply` dispatches all 79.** The six handler families between them name
  every ui and every engine variant.
- 112 files rewritten by a delimiter-aware transformer, not by regex: it
  balances `(){}[]` and skips strings and comments. Every file still balances.
- `linkcheck` 0 unresolved, shape 630 files, comment budget within, and 0
  public items lost from the 100+ touched files.

## Stage 5 — `engine::Session`

The reducer's first half. `Session` owns the settings, the pane tree, the
active pane, the panes by last focus and the route, and `execute(&mut self,
intent: Intent) -> Done` is the door. `Done` carries a `Focus` for what the
window alone can finish (a split needs the window's area; F6 also moves the
focus ring) and a `dirty` flag, so the engine never names `Context`, `Ui` or a
viewport command.

**It is built and it is not yet wired, on purpose.** The app still owns its
own copies of that state. Pointing only *some* of the 79 intents at `Session`
would leave two copies of the settings that must agree — a real divergence
bug, not an intermediate state. Delegation has to land intent-by-intent with
each one's readers moved at the same time, which is the next stage's work,
not this one's.

## Stage 6 — settings go through the door

`Session` is now the only copy of the settings. `MareaderApp` holds the
session and nothing else of them; `settings()` reads through it, and every
write — 52 field assignments, 10 `&mut` borrows handed to helpers, and the
two whole-struct writes — goes through `execute`.

The channel is `Intent::SetField { path, value }`, which is `Settings::set_path`
with a serde value: a dotted path like `text.font_size` to `17.0`. That is
what the review means by "the dotted-path command channel is nearly free",
and it means a new dial needs no new variant.

**Two things were caught by checking rather than assuming:**

- A cached `Arc<Settings>` was the first design. It reads cheaply, but it
  makes `settings_mut()` — which ~40 tests call — impossible to serve
  honestly, so the cache went and the session became the single copy.
- `set_path` sanitises, and it returns `Result`. Swallowing the `Err` would
  have made a mistyped path a silent no-op, so `Done` now carries `refused`
  and `set_field` hands it back as the handler's own error.

Behaviour: `sanitize()` is idempotent clamping and preset-dropping, so
running it on every write rather than occasionally cannot change a value a
clamp would have left alone. The one borrow hazard, `list_voices` taking
`&mut self` beside a settings reference, copies the sub-settings first.

## Stage 7 — the panes and the focus

`Session` now owns the pane tree, the focused pane and the panes by last
focus. `MareaderApp` keeps none of them: `tree()`, `active()` and `recent()`
read through the session, and every write goes through the door —
`FocusPane`, `ClosePane` (which also moves the focus when the closed pane
was focused), `CyclePane`, and `focus()`, the app's one way to move it.

`tree_mut()` exists for the two things `execute` cannot express: a lifted
pane dropped on another, and a divider drag. Those are pure geometry on a
tree the engine still owns, so handing out `&mut` keeps one copy without
inventing a variant for every pixel of a drag.

**The route stays where it is, deliberately.** `MareaderApp::route()` is
derived from `dict_from` plus `library.showing`, and the second of those
belongs to the library controller. Moving half of it would split a derived
value across two owners, so it travels with the library in the controller
stage.

**Two machine-caught breakages worth recording:** the rename turned
`Toast::active()` and `Picks::active()` — unrelated methods on other types —
into `self.active()()`, and `panes::show` needed the tree copied out before
a closure that borrows `self` mutably. Both were found by scanning rather
than by any test.

## Stage 8 — the reading place (part of `Documents`)

`PdfView` now holds one `engine::reading::Place` — the document, the book it
reads as, the page read, the mode, how far through, the spread's lead and
turn direction — and derefs to it, so the 1,480 lines that say
`view.current` or `self.mode` did not change. What a reopened window or a
headless client needs is now below the line; what a frame needs to draw
(offsets, laid-out rects, textures, quads) is not.

**What I tried and backed out, deliberately.** The rest of the split —
moving `Content` and the pane map down as a generic `Panes<T>` — I built,
then reverted. `Content::Pdf(Box<PdfView>)` would have had to carry a
`Place` *beside* the `PdfView` that also owns one, which is two copies of
the same reading state: the exact divergence bug the settings work was
rebuilt twice to avoid. Making it one copy means 59 match sites rewriting
what a `PdfView` *is*, and with no compiler that is a change I could not
verify. The honest position: `Place` moved, the map did not.

The marker stayed up too. It looked like reading state, but it is a word
plus a bar's animation — snapped, born, held — so it is chrome, and it is
still `PdfView::marker`.

## Stage 9 — `Place` gets one owner

The map is one copy per pane now. `Content::Pdf` is a struct variant
`{ place: Box<Place>, view: Box<PdfView> }`; the `PdfView` beside it holds
geometry and nothing that could disagree with `Place`. The `Deref` is gone,
and so are three second copies found while removing it — `doc`, `lead`, and
`landed` were each already a field of `Place`, and `lead` and `landed` were
dead: every reader had moved to `cx.place`, leaving their `PdfView` twins
written only at construction. That is precisely the divergence the map was
held back for, so they were deleted rather than kept in step.

Sixteen methods take the place: eleven as `at: &mut Place` where they move
it, five as `at: &Place` where they only read it. The parameter is named
`at`, not `place`: `place` is both a `PdfView` field (the re-set's anchor)
and a method name, and inside these bodies a parameter called `place` reads
the wrong thing.

Threading it found two calls the arity pass could not: `retypeset` still
called `self.go(page)`, and `paint/raster.rs` read `view.doc` twice in
functions that never bound `at`.

## Limits

- **Nothing was compiled.** The risk this stage carries is a missed
  re-export or an unused import (`-D warnings`); both were checked by the
  two link scripts and a name-level audit, neither of which is rustc.
- The `Place`/`PagesMenu` payload changes are the only places a ui-side call
  site had to learn a new shape. Both are arithmetic at the boundary, and no
  behaviour changes: the same numbers arrive at the same destination.

## Stage 10 — the reducer crosses the line

Checked against P2's exit gate at `6178397`, three of four lines were unmet:
the replay test opened nothing, `apply` matched `Command::Intent` itself, and
`command.rs` and `route.rs` still sat under `ui-egui`. This stage closes them.

- **One door.** `Session::execute(desk, intent, now)` in `crates/engine` is
  the reducer. What the session owns (settings, the tree, focus, the route) it
  changes itself; what a front-end controller still owns it asks for through
  `trait Desk` (`crates/engine/src/desk.rs`). `Desk` is the list of what P3
  has left to move: each method is a controller call that should become
  session state.
- **Results leave as data.** `Session::drain()` returns `Event`s: a toast,
  and the two focus-memory requests. Repaints leave through the `Waker`. Time
  arrives as `now: f64`.
- **`apply` in ui-egui** hands an `Intent` to the engine and matches on
  `UiCommand` only. `ui-egui/src/command.rs` is now `ui_command.rs` (chrome
  only) and `ui-egui/src/route.rs` is gone; `Route` and `reads` live in the
  engine, exhaustive over `Intent`.
- **The replay is real.** `crates/engine/tests/replay.rs` drives a windowless
  `Desk` (`tests/common/mod.rs`) over `mareader-session`: open the sample PDF,
  split, go to a page, select, highlight, export notes, and read the export.
- **Trapped 34 → 17.** Six files named toolkit types only through a glob and
  now import them by name. `word_card`, the byte LRU, `read_aloud::parts` and
  `counted` moved to the engine.

### Verified

Compiled this time, from the restored CI cache: `cargo clippy -p
mareader-engine -p mareader-ui-egui --all-targets -- -D warnings` is clean and
`cargo test -p mareader-engine` passes (54 unit, 5 replay).

### Not met, and why

- **Trapped is 17, the gate says below 12.** What is left is two controllers
  that name no toolkit but are not engine code yet: seven `library/*.rs`
  files that are `impl LibraryState` (P3 splits that controller) and seven
  `app/options*.rs` files that are `MareaderApp::set_option` (P4 moves the
  session-owned keys). `study/words.rs`, `trigger.rs` and
  `dial_deck/labels.rs` each lean on one front-end type.
- **`MareaderApp` is not `{ session, ui }`.** The controllers are still its
  fields; `Desk` is the seam they leave through.
- **Spec ids are kebab (`close-pane`), not dotted (`pane.close`).** Nothing
  reads them until the CLI in P5.

## Stage 11 — every intent has a dotted id

Law 3 names the shape of an id, not just its existence: `reader.open`,
`pane.split`, `mark.highlight`. All 60 rows of `SPECS` and all 60 arms of
`Intent::id` were renamed together, so the two cannot drift.

| Namespace | Holds |
| --- | --- |
| `pane.*` | splits, focus, close, ratio, zoom, view |
| `page.*` | turns, jumps, arrow keys, auto-scroll, copying pages |
| `mark.*` | highlight, note, bookmark, select |
| `word.*` | explain, look up, say, the two word-list asks |
| `read.*` | start, toggle, stop, the read marker |
| `voice.*` | try, try-of, models, revealing one |
| `library.*` | folders and scopes, its view, forgetting places |
| `dict.*` | packs, its settings, pronunciation |
| `settings.*` | the window, whole and single writes, looks, presets, chrome |
| `ai.*` | page tasks and the settings' background work |
| `export.*`, `study.*`, `vocab.*` | one row each |

**The registry's own test was a tautology and was replaced.** `id` is an
exhaustive match, so a new variant cannot build without a row — but the test
that claimed to check that only asked whether each id in `SPECS` was in
`SPECS`. `tests/specs.rs` now builds one of all 60 variants and asks each for
its row, which is the thing that was never actually proved. It was seen to
fail: deleting the `pane.zoom` row turns it red with `60 != 59`.

The 60 constructions live in five functions by namespace, because a function
stops at 80 lines and one list of them does not fit.

## Stage 12 — the app is the session and the window, and nothing else

P2's fifth item: `MareaderApp` shrinks to `{ session, ui }` and keeps
`impl eframe::App`. It was 55 fields, one of them the session; it is now two.

`UiState` (`crates/ui-egui/src/app/ui_state.rs`) holds the other 54, unchanged
and in their old order, `pub(super)` so the `app::*` modules that already
reached into them still can. Nothing moved between crates and no type
changed, so this commit is pure grouping: what it buys is that the seam is
now visible in the type. Reading `MareaderApp` says which half is the
engine's; a field added to the wrong half is a question the reader asks.

The 965 references were rewritten by a pass over the field list, then
corrected: 13 were multi-line chains (`self` newline `.documents`) that a
same-line pattern cannot see, and clippy named every one. Those were patched
from the compiler's own line and column and re-checked until none was left.

Kept deliberately:

- **`session` keeps its name and its place.** It is the engine's; `ui` is the
  window's. No `Deref`, no forwarding methods: a shim here would hide the
  split this commit exists to show.
- **The field is `ui`, and `MareaderApp::ui` is also a method.** Rust keeps
  fields and methods apart, so `self.ui` and `self.ui(ctx, frame)` coexist.
- **No controller moved down.** They are P3's and P4's work; `Desk` is still
  the seam they leave through.

### Verified

`cargo clippy --workspace --all-targets -- -D warnings` clean, `cargo fmt
--all --check`, `shape_check --dups` on 643 files, `comment_check` on all 179
changed files, and `xtask layers, trapped, parity, assets, unsafe` all pass.
Trapped stays 17: `ui_state.rs` names `egui::Rect` in two of its fields.

### Not met, and why

- **The controllers are still in `ui`.** Law 1 says the session should own
  the library, the marks and the read-aloud; that is P3 and P4.
- **Law 2 is not yet strict.** `Session::settings_mut()` and `tree_mut()`
  hand out `&mut` beside the door. Tests and shots use the first; a lifted
  pane dropped on another and a divider drag use the second, both pure
  geometry over a tree the engine still owns. `Session::execute_id` waits for
  the CLI in P5.

## Stage 13 — the trapped count, and why it stops at 17

**Closed by stage 14.** Everything below is the state at `c285d11`; the count
is 11 at the branch head and the gate passes.

P2's fourth gate line: `command.rs` and `route.rs` are gone from `ui-egui`,
which they are, **and the trapped count is below 12, which it is not.** It is
17. This section is the account of why, because the number is the one thing
in this slice that did not move.

The gate was written against P1's own gate, which says *the trapped count is
12*. P1 ended at **33**. P2 has taken it to **17**, so it has already paid
P1's debt as well as its own: the review asks P2 for two files
(`command.rs` and `route.rs`) and P2 has moved sixteen.

What is left, and what each file is waiting for:

| Files | Lines | What they are | What moves them |
| --- | --- | --- | --- |
| `app/options.rs` and its six children | 1,164 | `set_option`: the headless knobs `examples/shot.rs` and the tests drive | P4 item 5, which replaces every key that sets engine state with a command id and leaves only window size, hover point and platform skin |
| `library/{actions,books,duplicating,find,moving,organizing,shelving}.rs` | 1,855 | `impl LibraryState`: the library controller | P3, which names `library.rs` and `library/{io,folders}.rs` in its in-scope list; `LibraryState` has to cross before any of its `impl` blocks can |
| `study/words.rs` | 240 | a selection as a word to explain | P3: it leans on `crate::selection::Selection` |
| `trigger.rs` | 202 | a book's triggers, and the clips they play | P3: it leans on `crate::read_aloud::ReadAloud` |
| `dial_deck/labels.rs` | 27 | labels for the appearance dials, and a mode's icon | nothing: it is presentation. A false positive of a word-matching gate — `Icon` is not a toolkit crate |

The review says this itself. Its P1 section lists `trigger.rs`,
`study/words.rs` and six `library/*` files as **held**: "A held file moves in
the phase that moves its last egui-bound import: `command.rs` and `route.rs`
in Phase 2, the rest by the end of Phase 3." `library/shelving.rs` is the
one file that is not on that list: it became toolkit-free during stage 2,
when the comment that named egui travelled into the engine with `Carry`.

So the six files still needed for "below 12" are P3's and P4's. Three of the
seventeen could be moved now (`labels.rs`, `study/words.rs`, `trigger.rs`),
which would take 17 to 14 — not to 11 — and two of those need a front-end
type decoupled first, which is P3's work by the review's own rule.

**This is a blocker, reported rather than worked around.** The honest ways to
close it from inside P2 would be to widen `trapped`'s allowlist or to move
another slice's files; the first is a rules change and the second is another
slice's write-set. Neither is P2's to take.

## Stage 14 — the library's engine half, and the enum's name

Seven commits on top of stage 13, all of them paying down the same debt, and
stage 13's blocker does not survive them.

**The selection and its words** (`72149e5`). `study/words.rs` reads a text layer
and nothing else; `Caret` and `Selection` name only `TextLayer`, which the
session owns. All three go down — the words to `engine::study`, the two types to
`crates/session/src/selection.rs` — and the ui re-exports them at their old
paths. Trapped 17 → 16.

**The re-export goes** (`c4ca3d3`). The review's eighth limit says no shim
outlives its phase, so `ui-egui` names the two types where they now live instead
of re-exporting them. That cost `pdf_view.rs` the line its ceiling had no room
for, so `on_selection` moved to `paint.rs`, its only caller.

**`Intent` becomes `Command`** (`a86c07f`). Law 3's names are the review's:
`engine::Command` and `ui_egui::UiCommand`. The name `Command` was held in the
ui by the wrapper a view queues — it carried either an engine command or a
chrome one — so the wrapper becomes `Sent`, with `Sent::Engine(Command)` and
`Sent::Ui(UiCommand)`. A pure rename over 127 files: no arm, no branch and no
assertion moved.

**The library splits in two** (`c7b4f74`, `9672a18`, `18858c6`, `2d61149`,
`720e998`). `LibraryState` keeps what dies with the window — covers, folder
walks, the search, motion, the worker — and the engine holds the rest as
`engine::library::State`: the model, where the page stands, the picks, the
sheet, the held set and the queue of questions. A question is data (a clash, a
held file, a merge, a name already taken); only its asking was ever the window's.

Five files that named no toolkit were pinned in the front end by their calls
upward: a file dialog, a worker, a search cleared, a note on screen. The engine
now asks instead — `library::Out` is what it asks with, and one adapter in the
front end turns each ask into a command. Trapped 16 → **11**, which clears P1's
ceiling of 12 and P2's below-12 line together.

`720e998` is what the move cost, and settled. The held set used to ride on the
window's `Organizer`, whose clearing released it, so on the engine's state books
stayed held after their plan ran; and the questions were written to the engine's
queue while still read off `Folders`, so an answer given to one never reached
the other. One queue now.

## The re-export sweep, and what it cost

The last thing P2 owed was the vocabulary it re-exported on the way. Stages 1
and 2 moved the payloads below the line but left ui-egui binding each name at
its old path, so that the views above it kept compiling untouched. That was
right while the views had not moved; once stage 14 landed they had.

**Surface removed: 40 names across 17 modules → 0.** Every importer now names
the crate that owns the type. What is left in `crates/ui-egui/src` that begins
`pub use mareader_` or `pub(crate) use mareader_` is one line,
`lib.rs:73 pub use mareader_engine::documents::OpenRequest`, the entry point the
app and the shot harness both need.

The sweep is mechanical — `tools/sweep2.py` rewrites an import to the owning
crate's path and, where a name is used once or twice, names it where it is used
and drops the import — and its cost is all in the gates rather than the code:

- **rustfmt.** 125 files touched means every import block is re-sorted, and
  rustfmt's order is not the obvious one: it sorts `use` groups ignoring
  `#[cfg(test)]`, so a test-only name has to be imported inside `mod tests`, not
  at the file top; and a brace group such as `use crate::{icons::Icon, motion}`
  sorts *after* the plain `use crate::icons::anim::…` lines, not before. Four
  rounds of red, each one a diff smaller than the last.
- **the shape ratchet.** `tools/shape_check.py` holds every file to its current
  length, so the import lines the sweep added had to be paid back in the same
  files: same-prefix `use`s merged, blank-separated blocks joined. One merge
  deep only — a nested brace group is a line rustfmt splits straight back.
- **the comment gate.** It runs over changed files, so three comments in files
  the sweep touched, written long before it, had to stop narrating and state the
  constraint.

Checked by CI, not by eye: run `43257472846` on `0654cff` is green — `fmt`,
`clippy -D warnings`, `cargo test`, and all five gates: `shape: 648 files ok`,
`comment budget ok: 346 of 1040`, `71 of 71 subjects within 50 characters`,
`layers: 31 crates ok`, `trapped: 11 toolkit-free file(s); the count allows 11`,
`parity: 122.0 of 122`, `assets: 7 files`, `unsafe: 618 files`.

And checked without a compiler: `grep -rn "^pub use mareader_\|^pub(crate) use
mareader_" crates/ui-egui/src` returns the one line above; the in-tree
