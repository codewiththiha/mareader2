# G2 — the reducer

Branch: `refactor/engine-g2-reducer`, from `refactor/engine-g1-evacuate`
(`566b75f`). Review phase: P2 of the review site. This slice is the one that
makes Mareader engine-first, and it is being done in stages, each committed.

## Stage 1 — the types a command names

`engine::Command` cannot exist until everything it names can live below the
line. Moved, with ui-egui re-exporting each at its old path:

| Now in | Types | Was |
| --- | --- | --- |
| `engine::pane` | `ViewMode`, `Arrow`, `ZoomCommand`, `Step`, `Fit` | `ui::layout`, `ui::zoom` |
| `engine::documents` | `OpenRequest`, `Placement`, `DocumentPlace` | `ui::documents` |
| `engine::route` | `Route` and its `bar`/`has_rail` | `ui::route` |
| `engine::settings` | `Tab` (without the settings window) | `ui::settings_window` |

## Stage 2 — the rest of the payloads

- `engine::dict`: `Download`, `Window`, `Action`. **`Window::Place` carried an
  egui `Rect`; it is now `[f32; 4]`** — the same x, y, width, height the
  settings already store — per Law 5, "no pixels below L6". The arithmetic
  lives in one ui-side `bounds()` helper.
- `engine::page_ai`: `Action`, `How`, `Slot`. `Action::PagesMenu` carried a
  `Pos2`; it is now `[f32; 2]`.
- `engine::read_aloud`: `ReadFrom`.
- `engine::library`: `Action`, `Scope`, `Named`, `Sheet`, `ShelfAction`,
  `Carry`, `NEW_SHELF`, `BookAction`, `SearchAction`, `Finding`, `Step`,
  `CopyWork`, `CopyAnswer`, `Applied`; `Pick`, `PickAction` and `Picks` are
  re-exported from `mareader-library`, where stage G1 put them.

## Verified here (no compiler)

- **Nothing lost.** For all 18 touched ui files, every `pub` item at the
  branch point (`566b75f`) is still defined or re-exported: **0 lost**. Two
  were caught this way and restored — `Sheet` and `Crumb`, both of which sat
  inside blocks removed when their neighbours moved.
- **Derives unchanged.** Every moved type's derive list matches its baseline
  exactly. This caught two silent API breaks: `library::Action` and
  `CopyWork` had lost `Eq`, and `ViewMode` had lost `Hash`. All restored.
- `shape_check.py` and `--dups`: 629 files, no duplicates, no file over cap.
  Three files crossed their ceiling while being edited and were brought back
  by relocating code rather than raising a number.
- `comment_budget`: 321 of 856. `linkcheck`/`importcheck`: 0 unresolved.
- `trapped` 33 → **34**, and this is the one number that is worth explaining:
  `library/shelving.rs` counts as trapped-only-because-a-comment-said-egui;
  that comment travelled with `Carry` into the engine, so the file became
  genuinely toolkit-free. The ceiling follows it down the next time P2's own
  work removes the file.

## Limits

- **Nothing was compiled.** The risk this stage carries is a missed
  re-export or an unused import (`-D warnings`); both were checked by the
  two link scripts and a name-level audit, neither of which is rustc.
- The `Place`/`PagesMenu` payload changes are the only places a ui-side call
  site had to learn a new shape. Both are arithmetic at the boundary, and no
  behaviour changes: the same numbers arrive at the same destination.
